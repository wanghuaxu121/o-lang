# 为什么要有 O

> 一句话：O 是一门**内存完全透明**的编译型语言 —— 每个变量在编译期就有确定地址，
> `--map` / `--mem` / `--trace` 三个工具能把内存在任意时刻摊开给你看。

## 问题：内存被藏起来了

现代语言都在替你管理内存。GC 决定对象什么时候死，RAII 决定析构顺序，借用检查器决定谁能改，
优化器决定值到底在寄存器还是栈上。好处是省心，代价是：**你没法回答一个简单的问题 —— 这个值现在在哪儿？**

想看？上调试器、打日志、读汇编。调试器能给你栈帧，但给不了「第 6 号单元里现在是什么」，
因为那个编号在语言层面根本不存在。

## O 的答案：把地址变成语言的一部分

```o
O{
    &{int;a} = {int{0;9}} = {}      // a 占地址 0..9
    &{int;i} = {int{10}} = {0}      // i 在 10
    .{int; ${i}}
}
```

```
$ olang prog.o --map
 addr  名字
    0  int      x10  size=10  a
   10  int      x1   size=1  i
 静态区结束 = 11, 栈从 1023 向下
```

这不是调试符号，不是链接器事后补的 `.map` 文件，而是**编译器内部的布局本身**。
生成 C 时，同一个地址会变成字面量：

```c
_mem[(0) + 0].i = 0;     // a[0]
_mem[(10)].i = ...;       // i
```

**解释器里的 `a` 在 0 号，编译成二进制后 `a` 还在 0 号。** 这不是巧合 —— 两个后端共用同一套 layout，
并且有 39 个双后端探针在守这条线。

## 三个观察口

| 工具 | 看什么 | 例子 |
|---|---|---|
| `--map [--json]` | 编译期布局：谁住在哪个地址、占几个单元 | 给工具吃（链接脚本、仿真器、验证器） |
| `--mem [=all]` | 退出时内存快照，按变量/字段标注 | 审计程序到底改了什么 |
| `--trace` | 每条语句：行号、类型、`sp`、写了哪些单元 | 内存级单步 |

## 这能干什么

**1. 别名是写出来的，不是猜出来的**

```o
O{
    &{int;words} = {int{0;9}} = {}   // 0..9
    &{int;first} = {int{0;4}} = {}   // 也指向 0..4
    &{int;i} = {int{10}} = {3}
    ${first}{${i}} = {7}
    .{int; ${words}{${i}}}            // 7 —— 同一个地址
}
```

这是 MMIO 的同一套机制：把一段绝对地址绑定到外设寄存器，而不是另造一套访问路径。
`--walias` 会在区间重叠时给提示，但**不禁止** —— 禁止重叠等于阉割透明性。

**2. AI 写的代码，人能对账**

大模型生成的程序最麻烦的不是跑不起来，是「它到底动了什么」。O 的答案是跑完给你一张内存快照：

```
$ olang sms.o --mem
 addr  类型     值                     名字
    0  int      1                      a[0]
    9  int      10                     a[9]
   11  int      55                     s
```

279 个单元里，哪一格是谁、什么时候写的，全在。这是 C/Python 都给不了的证据链。

**3. 教学：栈帧是看得见的**

`--trace` 里 `sp` 从 1024 掉到 1021，再回来 —— 函数调用、引用参数写回调用者，全都摊在屏幕上，
不需要脑补。

## 代价（诚实说）

| 项 | 现状 |
|---|---|
| 性能 | 约 2.0× 手写 C（arm64，fib(40)），x86 更好 |
| 地址空间 | 默认 1024 单元 = 8 KB，可用 `#mem` / `--mem-size` 调到 1M |
| 动态内存 | 没有堆、没有 GC；数组长度编译期定死 |
| 表达能力 | 没有泛型、没有闭包、没有模块系统 |
| 生态 | 两个库：`sys`、`file`，加上刚做的 `str` |

## 不要用它做什么

- **写 Web 后端** —— 打不过 Go/Rust，而且会毁掉「无系统调用面」的沙箱属性
- **替代 C** —— 生态差太远，`@mmio` 都还没做
- **跑性能敏感的大程序** —— 2.0× 的差距是结构性的

## 适合谁

1. **PL 教学 / 语言实现课**：一份 3000 行的单文件实现，词法到 codegen 全在里面，
   `--map`/`--trace` 天生就是教具。
2. **需要审计的小程序**：特别是 AI 生成的、你要签字的那种代码 —— 内存快照就是签字依据。
3. **未来的嵌入式 / MMIO**：别名机制已经就位，缺 `@mmio` 和 `volatile`（SPEC §13 待定 6）。

## 现在能做什么

```bash
make                      # 编译（需要 g++/clang++）
./olang examples/hello.o  # Hello, O!
./olang examples/sms.o    # 学生管理：入学/转学/月考/分班
./olang examples/report.o > r.html   # 直接生成一张带 JS 图表的网页
tools/demo.sh             # 五个能力一次看完
```

- 测试 **90/90**，规范覆盖 **100%**（35 条可测条目）
- SPEC **v1.1**：内存模型、类型系统、字符串操作、双后端一致性都有成文条款
- §15 验收 **11/12**（性能那条还差一口气）

---

**O 的卖点不是快，也不是安全，是「你随时能指着屏幕说：这个变量就在第 6 号单元，编译前后都是。」**
这句话目前只有 O 能说。
